# UI の決まり（Shopee Smart Reply・WA Smart Reply・Zalo Smart Reply・Viber Smart Reply 共通）

2026-10-25 本人「おすすめどおり、1〜4と7・8・10を直して。5は押した回数を数えてから、6は試してからでいい。WA にも同じ決まりを当てて」。
もとのレビュー：Obsidian `10_shopee/Smart Reply UIレビュー_2026-10-24.md`（番号はそのノートの番号）。
見積もりカードの決まりは同じフォルダの `quote-card-spec.md`。

## 1. 1つの機能は1つの画面（UIレビュー 4）
- 引き出しのツール1つ＝見出し1つ＝中身1つ。**別のツールの画面の中に物を差し込まない**。
- 新しい物は、自分のツールを作るか、本人に置き場所を聞く。
- 例：仕入れ予定のリンクは 💴 見積もりの画面だけ（AI 候補・定型文・返し忘れには出さない）。見積もりカードは 💴 の画面だけ。
- 同じ物を2つのツールに並べて出す作り（表示の条件に別のツールの画面を2つ以上並べる）をしない。

## 2. 数字の札には名前を常に出す（UIレビュー 2）
- 札の意味をマウスを乗せた時の吹き出し（title）だけにしない＝「押さないと出ない・開かないと見えない」を作らない。
- 札の下（または横）に2〜4字の名前（未返信・未読・返信時間・エラー など）。
- 毎日見ない物は「もっと」へ。数字が 0 の札は**消さずに薄くする**（WA も同じ・10/25 03-22 の相談に答えた）。
- 札の表示と吹き出しの中身を合わせる（例：中身が「直近7日に失敗 8件」なら表示も失敗の件数）。

## 3. 「未返信」は1つの画面（UIレビュー 3）
- 返していない会話は「📮 未返信」の1画面にまとめ、中のタブで「未返信／暫定返信／7日経過」を切り替える。会話を1件ずつ開いて探す「全件確認」は、その画面の中のボタン。
- 未返信の正は会話ログから作る 📮（chat_unanswered）。画面の未読バッジや巡回は補助。

## 4. 色の意味（UIレビュー 7・9）
- 赤は本当に失敗した時だけ。入力を待っている状態（「探す品名を入れて ↻」など）は灰色の案内。
- 入力欄の枠：**空は入力待ち＝灰色の点線**。**誤り（例：英語の商品名に日本語）だけ赤枠**。quote-card-spec 8.2・8.3 の「空なら赤枠」は 12-10 でこれに置き換えた（10/25 03-22 の相談に答えた）。
- オレンジ＝Shopee の色（見出し）、赤＝失敗、緑＝送る準備ができた、灰＝案内。※色の付け替え（9）：見積もりカードの「入力欄へ入れる」は 2026-11-04 本人「よろしく」で緑に決定（SR 6.19.73・WA と同じ #25d366 の塗り・白い字）。
- 定型文などの「📥 挿入」「🈂 入力欄へ入れる」も、入力欄へ入れるボタンなので同じ緑（#25d366・白い字）にそろえる（2026-11-06 03 の決め・4つの道具とも。Zalo の全体レビューで SR は青・WA と Zalo は橙とずれていた）。

## 4.5 💴 見積もりの始め方（10/25 03-22 の相談に答えた・SR の形）
- 見積もりの入口は**右端の 💴 ボタン1つ**。押すと 💴 の画面を開いて、「仕入れ予定の行（額あり）→ 前の見積もり → お客さんの発言」の順で始める（quote-card-spec 12-2）。
- 💴 の画面の中にあるのは、カード（↻ 計算し直す・📌／🔎 探し直す・🔎 お客さんの発言から新しく探す）と、その下の「🛒 仕入れ予定のリンク（この人）」の欄（行ごとの 💴 見積もり・🛒 Request page へ・足す・直す・消す）。
- **AI 候補・定型文など、ほかのツールの画面に見積もりの入口や仕入れ予定の欄を置かない**（1 の決まり）。WA で右端のボタンが無い作りなら、💴 の画面のいちばん上に「💴 この会話で見積もりを作る」を1つ置く形でよい。

## 5. 勝手に開く物・消えない通知（UIレビュー 8）
- 自分から開く小窓は「何か見つかった時だけ」開く。見つからなかった結果は、ボタンの小さな印だけ（押せば開く）。
- 通知は、押す場所（どのボタンか）を書くか、要らなければ出さない。自動で済んでいることを手でやれと言う通知は出さない。

## 6. 文字の大きさ（UIレビュー 1・10）
- 本文・案内・ボタンは 11px 以上。注記だけ 10.5px まで。**10.5px より小さい字は使わない**（9px・10px も使わない）。
- 右端のボタンの名前は 11px・2行まで（「過去の答え」が2行で入る）。
- 入りきらない時に字を縮める処理も、10.5px より小さくしない。

## 7. ボタンを押した回数を数える（UIレビュー 5）
- 並び替えは推測でしない。ボタンごと・日ごとに押した回数を GM に数え（30日）、1週間分を見てから本人と決める。
- Shopee Smart Reply：GM `sar_tap_counts` ＝ { 'YYYY-MM-DD': { ボタンのid: 回数 } }。ページから `postMessage({ sarTapExport: 1 })` → `<html data-sar-tap-export>` で読める。

- 見ているのは書き方の形だけ。差し込みの全部は見つけられない（目でも確かめる）。

## 9. 道具が埋められる値で止めない（2026-11-06 本人の決め）
本人「なんでさ、ラクにするのが目的でこのツール作ってるのに、一手間食わせるの？」（SR のまとめ買いの見積もりが「品物ごとの英語名を入れてから ↻」で止まった件・事業本部経由）。
- 道具が自分で作れる・推せる値（英語の商品名・重さ・目標の粗利の既定・カテゴリなど）が空の時に、「入れてください」で止めない。自動で埋めて先に進む。
- 自動で埋めた値には「自動」の印を付け、その場で直せるようにする。本人が直した値は「指定」とし、道具は上書きしない。
- 止めてよいのは、間違えるとお金やお客さんに響く物だけ。例：
  - 写真が無いのに出品する。
  - 為替が既定のレートのまま値段を出す。
  - VN の上限を超える。
  - 別の人の会話に入れる。
  - 二重に出品する。
  - 合意の額と違う額で足す。
- 止める時は、理由と、次に押す物を1つ添える（4. の色・5. の決まりのまま）。
- 4つの道具（SR・WA・Zalo・Viber）で同じにする。

## 11. 4つの道具をそろえる・点検（2026-11-07 本人「一気に直してって」「毎回」「shopee smart reply 側の仕様とかと揃ってないし」）
- 基準は Shopee Smart Reply（SR）。WA・Zalo・Viber の見積もりの右の列（見出し・相手の帯・注文の箱・仕入れ予定の行・見積もりカード・ボタンの色と大きさ）は SR に合わせる。SR に無くて他にある良い物は SR に足す。
- どれか1つの道具で直したら、同じ日のうちに4つ全部（とポータル・GAS の同じ口）の同じ所を直して入れる。「次の版で」にしない。頼む文に「ほかの道具も同じ直し」を毎回書く。
- 仕様は quote-card-spec.md とこの ui-rules.md の2つだけ。道具ごとの別の仕様は作らない。
- 点検：`python3 tools/parity-check.py`（機能の一覧は tools/parity-features.json）。版を上げるたびに回し、❌ が出たら同じ日に直す。新しい機能を足したら、一覧にも1行足す（足さないと点検に出ない）。
- 11/7 の突き合わせ（03 共有フォルダの 03突き合わせ_見積もりの右の列_SR基準_2026-11-07.raw）で決めたこと：
  - 🧾 注文の箱は SR の形にする（相手の帯の下に常に出す・見出しで畳める・2件と「あと N 件」）。
  - ① の「✅ 送った（印を付ける）」は WA・Zalo の形にする（入れただけでは印を付けない・spec 22.1）。SR もこれに合わせる。
  - ボタンの字は 11px 以上（6 の決まりが正）。SR の 10.5px の3か所も直す。
  - 内部の言葉（quote-card v1/v2 の表示）は、どの道具も出さない。
  - SR に無くて他にある良い物（仕入れ予定の行の「🤝 合意済み・次は…」の札、しまった行の 💴・✅ 足し済み、写真の枠を常に出す・photos[0]・「写真なし ↻」、🧾 の開いた状態を覚える、⑦ 買ってもらった（spec 22 の状態で）、選び方の画像の「画像をコピー」、計算中は ↻ を押せない、「← 今の見積もりへ戻る」）は SR に足す。

## 12. 絞り込みの帯の作り方（2026-11-07 本人「ここも見にくいんだよな」・ポータル 👣 アクセス（各国）のグラフの上の5行）
- ふだんは「いま」の1行だけを出す（例「🌏 すべての国・訪問者・1か月（1日ごと）・📈 折れ線・前の期間を重ねる」）。「⚙ 変える ▸」で開く。開いた・閉じたは端末に覚える（ポータルは smdTaFold）。
- 開いた時：
  - 1つだけ選ぶ物（期間など）は1行の区切りボタン（つながったボタン）。
  - 2択（国ごと／アカウントごと など）は2つの切り替え。
  - 店は国ごとにまとめる（国旗＋国の名前の横に「本店／2店舗目／両方／なし」の選択欄）。店の数だけ丸を並べない。
  - 指標は、よく使う4つ（訪問者・ページビュー・注文数・売上）を出し、残りは「その他 ▸」。
  - グラフの種類はアイコンだけの小さなボタン（名前は title に）。
  - 重ねる物・足す物（7日移動平均・前の期間を重ねる・国ごとに分けて並べる）は ☑ の切り替え。
- ラベルの列（期間・単位…）の幅を揃える（44px）。ボタンの高さ（26px）・字（11.5px）・間隔を揃える。
- 保存している設定の意味は変えない（帯の形を変えても、前に選んだ物がそのまま効く）。

## 13. 長い表の見出しは固定（2026-11-07 本人「スクロールしたら列名がきえる」）
- 行が画面より長くなる表は、見出しの行を position:sticky で上に残す。上の固定の帯の高さ（ポータルは --smd-bar-h）の分だけ下げて止め、背景を付けて下の行が透けないようにする。
- 横スクロールの箱（overflow:auto）に入れると止まらない。箱で囲む時は箱の中で縦にもスクロールさせる（ポータルの .pf-scroll・.pf-table の形）。
- ポータルで同じ作りの物：.pf-table（.pf-scroll の中）・🏆 .prk-tbl・出品管理の見出し・👣 アクセスの商品の表（.ta-ptbl）。

## 14. 商品の行には写真・カタログ名・明細名（2026-11-07 本人「こういうのぜんぶ画像欲しい」「このページ以外も」「文字だけでわからないもん」「カタログ名とか、明細名とか」）
- 商品が行・カードになる一覧は、最初から 小さい写真（36px 前後）＋1行目カタログ名＋2行目明細名（小さめの字）で作る。名前だけの一覧を新しく作らない。
- ポータルは共通の部品 `itemCellHtml(items, opts)`（写真だけは `itemPhHtml(src, size)`）を使う。写真は `loading="lazy"`・`class="zimg"`（全ページ共通の拡大が効く）。
- 写真が無い時は同じ大きさの灰色の箱「写真なし」を置く（行の高さを崩さない・箱を消さない）。
- 2品以上の注文は全品を並べる（`items[0]` だけにしない）。
- 名前は slice で切らない（CSS の … と title に全文）。
- 写真・明細名のために読み込みを増やさない。今その画面が持っているデータ（注文の items・出品の models・読んである出品）から引く。
- 在庫（inventory）には明細の欄が無い。明細名は Shopee注文SN が手元の注文に当たる時だけ出し、当たらない時は「明細：—（在庫に明細の欄なし）」と理由を書く（空のままにしない）。
- 商品ごとの数（カート・ELI の提出など）で明細が無い物は「明細：—（…は商品ごと）」と書く。

## 15. 区分の丸ボタンは3段（大・中・小）（2026-11-07 本人「これは多すぎるから、もっと大項目、中項目に分けた方がいい」・👣 アクセス（各国）の機種の丸が約80個並んでいた）
- 機種などの区分の丸ボタンを1行に全部並べない。①大項目 ②中項目 ③小項目（機種）の3段にする。
  - ふだんは①大項目の1行だけ（「すべて」が選ばれた状態）。
  - 大項目を押した時だけ②中項目の行を出す。中項目を押した時だけ③機種の行を出す（中の機種が1つだけなら出さない）。
  - 同じボタンをもう一度押すと外れる。大を選び直すと中・機種は外す。
- どのボタンにも件数を付ける。件数は、ほかの絞り込み（国・店・期間・商品名など）を通った物で数える。0件の物は出さない（選んでいる物だけ薄くして残す）。
- 新品・中古は大項目にしない。①の行の横に「すべて／中古／新品」の切り替えを置く。新品＝名前が New・[New]・新品・新 で始まる物（New Super Mario など題名の New は除く）。
- 分け方はポータルの1か所だけ：`hwTierOf(name, hw)` → { big, mid, hw, nw }。名前の正規表現は `HWT_RE` だけに足す。画面ごとに別の分け方を作らない。
  - 大項目：🎮 ゲーム／🕹 本体・周辺機器／📱 電子ペット／🃏 トレカ／🧸 グッズ・おもちゃ／🎰 一番くじ／📦 その他（中項目は `HWT_MID`）。
  - 機種は、明細 SKU を持つ画面では SKU の頭（PS3_…・`LLOG_SKU2HW`）を先に渡す。無ければカタログ名・明細名から（`hwOf`）。
  - 本体・コントローラ・メモリーカード等は、機種が付いていても名前で 🕹 に分ける。
- 帯の部品：`hwTierBarHtml(list, sel, opts)`（描く）・`hwTierBind(host, cls, sel, onChange)`（押した時）・`hwTierPass(t, sel)`（絞り込み）・`hwTierFix(sel, list)`（前に保存した機種から大・中を選び直す）。行が機種そのものの表は `noHw`、名前の無い物は `noNew`。
- 前に保存した選び（機種だけを覚えていた設定など）は消さない。その機種の大項目・中項目を自動で選んだ状態で開く。
- 字・高さは 12 の帯と同じ（ボタン 11px・ラベルの列の幅をそろえる）。1470px の幅で、閉じた時は1行・中項目まで開いても2行に収める。
- ポータルで入れた所：👣 アクセスの商品ごと（ta-hwt）・📅 出品ログの日別（llog-hwt）と自動で出した明細の表（llog-tottier）・📚 母数（tm-cat に 🎰・中項目 tm-mid）・🏆 商品別の利益（pr-hwt）。

## 12. 定型文のジャンル「🔍 状態・動作確認」（2026-11-07 本人「状態の括りとかないの？」・00 経由）
- 4つの道具（SR・WA・Zalo・Viber）とも、同じ札の名前「🔍 状態・動作確認」を、「商品・付属品」のすぐ右に置く。
- 入れる物：商品の状態（中古の傷・汚れ・日焼け）・動作確認済み・状態の写真を送る／送った・箱や説明書の傷み・電池・セーブ・状態の希望を聞く。
- 今「商品・付属品」「紛失・在庫切れ・不具合」「状態・商品」などに入っている物を1本ずつ見て移す。どちらにも当たる物は、主な方に1つだけ入れる（2つの札に同じ物を出さない）。
- WA・Zalo・Viber の「🔍 状態・商品」は、「商品・付属品」と「🔍 状態・動作確認」の2つに分ける（例：Zalo z-cond「状態の希望を聞く」→ 状態・動作確認、z-jpver「日本版です」→ 商品・付属品）。
- 状態の写真（コンディション画像）の仕組みがある道具は、この札の一番上に「📷 状態の写真を探す（この会話）」を置き、ここから使えるようにする。
- 移したら、ほかの札の件数も数え直して、画面の数と合うかを確かめる。parity-features.json に「tpl-genre-cond」を足す。
- ほかの札の名前と並びも、4つで違う所がある（SR は Shopee のチャット向けの札が多い）。そろえるのは次の決めとする。今回は「🔍 状態・動作確認」の札と、その前後の「商品・付属品」だけをそろえる。

## 13. 営業：相手を指定して送る（2026-11-07 本人「これ、顧客名指定で送ることってできる？」・00 経由）
- 📣 営業の画面に「👤 相手を指定して送る」欄を置く（WA・Zalo・Viber で同じ形・同じ場所＝「📤 今すぐ1人に送る」のすぐ下）。
- 名前（Shopee のユーザー名・WhatsApp の名前・顧客リストの名前）か電話の一部を打つと、台帳と顧客リストから候補が出る。候補ごとに国・最後に買った日・営業の段階（未送信／送った日／返事あり／申請中／断られた）。
- 候補を選んで「📤 この人に送る」：いつもと同じ営業の文面を1通。送った・返事あり・断られた人は赤字で出し、もう一度押した時だけ送る。
- 今開いている会話の相手が台帳にいれば「この会話の人に営業を送る」も押せる。
- 守る物：BR の夜の決まり・前の1通から9分（GAS の窓口 v7 の wait:true と同じ「あと N 秒」）。1日の上限は 📤 と同じく手で押した1通は超えてよい。送ったら台帳に書き、自動の営業が同じ人に二重に送らない（auto-send-once）。
- GAS の窓口に「相手を指定して1人を返す」口が要る（05）：outreach_next に phone=（または outreach_pick）を足し、同じ LockService・予約の行・9分の間あけを通す。
- Zalo・Viber は友だち申請の道具（zalo_ops）で、指定した1人に申請または案内を1通送る形にする。
- 試しの送信は自分宛ての会話だけ。お客さんには送らない。
- 追記（11/7 本人「営業ではなく、文章も指定にしたい時のパターンもある」）：
  - 相手を指定した後に、送る文を「営業の文面／定型文から選ぶ／自由に書く」の3つから選ぶ。自由に書く時は日本語で書けば英訳を出し、英語で送る（お客さんへの文は英語だけ）。写真も付けられる。
  - 営業以外の文は、営業の上限・9分の間あけ・台帳の段階に数えない。送った記録は会話ごとに残す。
  - Shopee で送れなくなった相手（Maximum number of messages sent reached など）に、WhatsApp・Zalo・Viber から連絡する入口にする。SR にも「📲 WhatsApp で送る」を付け、顧客リストに番号がある人ならその文を持って WA の画面に渡す。番号が無い時は「番号がありません」と出す。

## 14. 日本語のまま送らせない（2026-11-07・PH nilssonnils に本人の日本語の文がそのまま送られた）
- 4つの道具とも、お客さんの入力欄に日本語（ひらがな・カタカナ・漢字）が入ったまま送ろうとしたら止める。送信ボタン・Enter の前に「日本語のままです。英語に置き換えますか」を出し、「英語に置き換える」「このまま送る」「やめる」を選ばせる（「このまま送る」は確認つき）。
- 止めるのは本人が送る時だけで、道具が勝手に送ることはしない（送信の自動化はしない）。英語の文の中の品名（日本語の題名）は、品名だけの行なら止めない（決め方は担当が実物で決めて 03 に返す）。
- 14 の追記（11/7・9/16 の決まり「Shopee のチャットでは cancel は禁止語」・記憶 shopee-chat-no-cancel-word）：Shopee のチャット（SR）に送る文に cancel／cancellation／canceled／cancelled が入っていたら、送る前に止めて「Shopee では withdraw に置き換えますか」を出す（押せば置き換える）。自由に書く文の英訳も、Shopee 向けなら cancel を使わず withdraw で訳す。WA・Zalo・Viber の「自由に書く」から Shopee に渡す時も同じ止めを通す。外のアプリ（WA・Zalo・Viber）で送る文は止めない。
- 13 の追記（11/7・GAS の口・顧客情報抽出 GAS＝営業窓口と同じ鍵）：
  - `customer_find`（q＝Shopee のユーザー名・受取人名・アプリの名前・電話の一部）：顧客リストの全部の国のシートと「営業送信」に加え、Drive の今日の注文の書き出し（顧客リストに入る前の分）も見る。候補は10人まで。返すのは id・国・Shopee 名・名前・最後に買った日・営業の段階（営業送信の最後の状態）・番号のある無し・伏せた番号（頭4字…最後3字）。電話番号そのものは返さない。
  - `customer_get`（id）：選んだ1人の番号だけを返す（WA が会話を開くため）。
  - `wa_handoff_put`（phone か customer id・text・img の URL・from＝sr）：SR が文と相手を置く。30分で消える。`wa_handoff_get`（dev）：WA の「この端末で営業を送る」が ON の端末の dev だけが読める。1回読んだら消す。
  - ログには電話番号を丸ごと残さない（頭4字…最後3字だけ）。
- 13 の追記2（11/7 本人「だから、これ、ベトナムとかやとzaloになるやん？」・00 の決め）：上の「📲 WhatsApp で送る」「wa_handoff_put／get」は、次の形に置き換える。
  - SR の入口は「📲 外のアプリで送る」。渡す先は国とお客さんで選ぶ（VN＝Zalo／PH＝Viber か WhatsApp／ほか＝WhatsApp）。営業の台帳で連絡の取れたアプリを先に出す。
  - 口は `handoff_put`／`handoff_get`（app＝whatsapp|zalo|viber を付ける）。読めるのは、そのアプリの営業の端末だけ。30分で消え、1回読んだら消える。
  - `customer_find`／`customer_get` は、連絡の取れるアプリ（台帳の送った・返事あり・友だち済みの物）も返す。
  - 受け取る側（WA・Zalo・Viber）は、自分のアプリ宛ての handoff を読み、相手の会話を開いて入力欄に入れる（送信は本人）。会話を開く前に、入力欄が空・本人の操作が3分無いことを確かめる。日本語・cancel の止め（14）も通す。

## 16. 定型文には、伝わる物は全部絵を付ける（2026-11-07 本人「極力、必要なやつは全部画像欲しいですね」「文字読まないので海外の人」「あれ？これ画像お願いしなかった...?」）
