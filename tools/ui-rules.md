### 0.6 1回押せば進む（2026-11-13 1時台・本人「ほんといい加減にさ、ちゃんとやってくれよ」・BR caue.arua で「🛒 387 BRL で Shopee に足す」が何も起きなかった・00 経由）

### 0.13 スクロール中にチカチカさせない（2026-11-13 本人「これさ、スクロールしたときにガチャガチャ表示されるのやめてほしい」→言い直し「ガチャガチャっていうか、スクロールがチカチカなるのをやめてほしい」・SR 6.19.228 前後・z_junior_1986）
- 困りごとは、跳ねるより、スクロール中に画面がちらつく（点滅する）こと。スクロールしている間は、道具が吹き出しや右の列の DOM を書き換えない（訳・🤖 の印・送ったの印・未読の数・見張りの描き直しなど全部）。止まって 150ms たってから、まとめて1回だけ書く。
- 一度消えて出直す作り（opacity・display・visibility の切り替え・innerHTML の丸ごと入れ替え）をやめ、変わった所だけ書き換える。
- 確かめ：スクロール中の道具の DOM の書き換えの回数を数えて 0 回（止まってから1回）にする（tools/ui-audit.js の uiScrollWrites）。
- 本人「定まってほしい」（00 経由）：スクロールした位置と画面が、ちらつかず・動かずに止まっていること。止まった後に訳や印を付ける時も、見ている吹き出しの位置が1ピクセルも動かない（付ける分が見えている所より上に入るなら、その高さだけスクロール位置を足して保つ）。確かめは uiJitter の「見ている吹き出しの位置のずれ」0px。
- 見立て（推測）：webchat はスクロールで吹き出しを作り直す。そのたびに道具が和訳を消して付け直すので、吹き出しの高さが変わり、画面が跳ねる・ちらつく。
- 和訳は発言ごと（発言の id か本文の字で作った鍵）に一度だけ作り、控えから出す。スクロールのたびに訳し直さない・消さない。
- 吹き出しが作り直されたら、控えの訳をすぐ同じ高さで戻す。「訳しています…」の一時の表示で高さを変えない（訳の欄の高さを先に取っておく）。
- 付け直しは、スクロールが止まってから（150ms 待って）まとめて1回だけ。自分で付けた訳の変化で MutationObserver がまた呼ばれる輪を作らない。
- スクロールの位置が跳ねないこと（付けた分だけ下に押される時は位置を保つ）。

## 1. 1つの機能は1つの画面（UIレビュー 4）
- 引き出しのツール1つ＝見出し1つ＝中身1つ。**別のツールの画面の中に物を差し込まない**。
- 新しい物は、自分のツールを作るか、本人に置き場所を聞く。
- 例：仕入れ予定のリンクは 💴 見積もりの画面だけ（AI 候補・定型文・返し忘れには出さない）。見積もりカードは 💴 の画面だけ。
- 同じ物を2つのツールに並べて出す作り（表示の条件に別のツールの画面を2つ以上並べる）をしない。

## 2. 数字の札には名前を常に出す（UIレビュー 2）
- 札の意味をマウスを乗せた時の吹き出し（title）だけにしない＝「押さないと出ない・開かないと見えない」を作らない。
- 札の下（または横）に2〜4字の名前（未返信・未読・返信時間・エラー など）。
- 毎日見ない物は「もっと」へ。数字が 0 の札は**消さずに薄くする**（WA も同じ・10/25 03-22 の相談に答えた）。
- 札の表示と吹き出しの中身を合わせる（例：中身が「直近7日に失敗 8件」なら表示も失敗の件数）。

## 3. 「未返信」は1つの画面（UIレビュー 3）

## 30. 連絡先の名前（2026-11-15 04時台・本人「まだ登録名バグってない？これ全部直してって言ってるじゃん」「今後一切こういうことがないようにしてください。他も全部見てください。」・00 経由・WA の見出し「_BR FARIAS NUNES(empatandosebogeek) FARIAS NUNES(…) …」）
- 正の形は1つ：「<名前>(<Shopee のアカウント名>)_<国2字>」。例「Renata Triviño de Oliveira(renatatrivino)_BR」。
- 名前を作るのは、顧客情報抽出 GAS の clFullName_(name, acc, cc) の1か所だけ（05）。People API では givenName にだけ全文を入れ、middleName・familyName は空。WhatsApp は欄をつなげて見せるので、2つの欄に入ると名前が並ぶ。
- 4つの道具（SR・WA・Zalo・Viber）は名前を組み立てない。連絡先を足す・直す時は contacts_add を呼ぶだけ（名前・acc・cc を別々に渡す）。WhatsApp の「新しい連絡先」の画面に名・姓を打ち込む形にしない。
- すでに「(acc)_CC」が付いた名前に、もう一度付けない。組が2つ以上・_CC が頭や真ん中・化けた字（ﾃ｡ など）は、書く前に直す。直せなければ書かずに記録だけ残す（GAS 側の止め）。
- 書き換えてよいのは、うちの道具が作った連絡先だけ（Shopee_国 のラベル、または (acc)_CC の形がある物）。本人が手で付けた名前・お客さん以外の連絡先は触らない。番号は国番号を含めた全体の一致で見る（同じ名前で別の番号を使う人がいる・末尾の一致は候補まで＝11/8 の決め）。
- 連絡先を消さない。全件の直しを流す前に、dry で型ごとの件数と例（番号は末尾3桁）を 00 に見せる。

## 31. 2台の PC で上書きし合わない書き方（2026-11-15 07時・取込GAS v90・同期 GAS v5）
- 🔒 ロック（follow_put）：掛ける時は onAt、外す時は offAt（ミリ秒）を必ず付けて送る。メモ・期限だけの書きは onAt を付けず memoOnly:1 を送る（v91：ロックの on/off は変えない・外れていれば stale:true・memoSaved:true が返る＝手元のロックを外す・メモは書けている）。古さの判定は2分の幅つき（PC の時計のずれで新しい操作を捨てない）。返事が stale:true なら、サーバーの方が新しい＝手元を返事の row に合わせる（もう一度送らない）。
- 仕入れ予定・行のメモ（pa_cache_put）：読んだ時の ver を覚えておき、書く時に baseVer として付ける（行がまだ無い時は空文字）。返事が conflict:true なら、返事の rec（今の中身）と手元を url ごと・memoAt ごとに新しい方で合わせ直し、新しい ver を baseVer にして1回だけ送り直す。2回目も conflict なら送らず、柱に「ほかの PC と同時に直されました（このPCには保存）」を出す。busy（ほかの書き込み中）は30秒後に1回だけ送り直す。
- 定型文（同期 GAS の userTemplates）：1定型文の丸ごと（tools・pics・ja・noteJa・updatedAt）を送る。向こうにしか無い定型文も取り込む。同じ id は新しい方。消す時は deletedAt を付けて送る。userTemplatesFull:true は使わない（ほかの PC の分を消す筋）。（同期 v6・08:0x）取りに行く時は ?ut=1 を付け、userTemplatesSrv（消した印の無い物だけ）で受ける。既定の GET は userTemplates を返さない＝道具が消す時に deletedAt を送るようになるまで（生き返りと重さを防ぐ）。
- 4つの道具の定型文の置き場は、この同期 GAS の1か所にまとめる（移す順は SR→WA→Zalo→Viber・今の置き場は消さず控えに）。
- 確かめは、本物の呼び出しが通った時の返事（ver が返るか・stale／conflict の形）で見る。試しで本物の行を作らない（試しの名前 zsrdrytest などを使う）。
